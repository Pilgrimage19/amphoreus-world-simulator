# 2026-10-19 历史列表撑高页面修复

## 请求与原因

用户截图显示“难民与资源危机”卡片不断堆积已结束事件，导致整个网页很长。原页面将全部记录渲染为自动高度网格，没有设置列表高度上限或内部滚动。

## 修改

- 为难民与资源危机、黑潮危机、最近历史、组织与势力、已故因子行者及逐火史添加统一 `scroll-list`。
- 最大高度使用 `clamp(16rem,45vh,28rem)`；少量内容按实际高度展示，历史增多后只在框内滚动。
- 标题仍位于列表外，不随记录滚走；滚动条与现有深色主题一致。
- `tabindex`、命名区域、可见焦点支持键盘操作；滚动边界不继续传递到页面。
- 未修改模拟、事件生成、排序、数据接口或记录数量；没有重启服务、推进或重置用户世界。只刷新静态页面进行验收。用户继续测试时观察到年份从 636 增至 646，这不是本次验收操作推进的。

## 验证

- 项目专属 Conda 环境完整测试：108 项全部通过，17.982 秒。
- 新增 HTTP 静态页面回归测试，检查六类列表的滚动容器和键盘/无障碍属性。
- JavaScript 语法与 `git diff --check` 通过。
- 真实浏览器宽 698、高 828 的视口，第 646 年共 179 条难民危机：列表高约 373 像素，内容高约 15385 像素；历史页总高约 2673 像素，不再随该列表无限增长。
- 键盘 PageDown：内部 `scrollTop` 从 0 到 326，页面 `scrollY` 保持 1507；控制台警告/错误为空。
- 验收截图：`docs/audits/2026-10-19-history-scroll.jpg`。

本轮只修复观察端布局；10 月 3 日自然世界线审计数据与待校准设计不变。
